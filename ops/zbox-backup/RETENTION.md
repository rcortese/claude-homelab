# Policy A: non-destructive retention selection

Run `python3 retention.py /absolute/backup/base` on the destination, beside generation.py. This is read-only; extra arguments fail. It never deletes, writes a receipt into a generation, updates pointers or launches capture. Applying this helper to production requires the applicable human deployment authorization.

The unit of retention is the complete sealed generation: payload, dump, provenance, inventory and validation metadata. All valid generations are reverified before classification. Keep the newest valid point for each of the newest 31 represented UTC days, plus the newest valid point at or before the rolling 30-day boundary when available. Always protect the authoritative latest generation, including after prolonged capture failure. Sparse captures cannot manufacture a 30-day history. A count of 31 is not a strict maximum when the boundary anchor or last good adds protection.

Historical/unsealed, malformed, symlinked or unexpected snapshot entries are protected, never treated as removable. Incomplete attempts are separately protected. Unsafe roots/pointers and an invalid latest stop selection. `remove-candidate` is a proposal, never authorization; no execution/deletion interface exists. Subsequent cleanup needs exact freshly verified targets, corresponding authorization, locking and drift reconciliation. This candidate intentionally does not implement that destructive executor.

Policy authority: Rodolfo's decision in TAC-543 comment b71e5db8-7643-4361-8861-22c8e72d30a6. Daily capture, 31 daily points, >=30-day anchor, last-good protection, initial 140 GiB new-data envelope and three incomplete attempts. The envelope is an estimate, not measured capacity reservation; this selector does not enforce it. Producer already caps incomplete attempts. Existing historical config SNAPSHOT_KEEP=14 and DUMP_RETENTION_DAYS=14 is obsolete and unused by the current no-prune producer; deployment reconciliation must explicitly retire it, not re-enable legacy pruning. No new coverage/exclusion, new secret custody, encryption or restore claim is made here.

Tests: `python3 test-retention.py` and `python3 test-generation.py`. Synthetic fixtures include coherent seals, corrupt dump, unexpected links, preserved legacy and incomplete attempts, sparse points, duplicate days, long failure, future/unsafe identities, deterministic output and before/after inventory equality.
